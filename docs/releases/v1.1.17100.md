# AgentDock Workbench 1.1.17100 — Windows x64

Workbench v1.1.7을 기준으로 한국어 표시, 고정된 ripgrep 번들과 확인된 최소 결함 수정을 적용한 Windows x64 배포입니다. 내부 프로토콜과 기존 설치 식별자는 유지합니다.

## 변경 사항

- Windows 제어판·실행 창·권한 설정·추가 메시지 상태와 Setup, 브라우저 상태/OAuth 페이지 및 MCP Apps에 한국어 표시를 연결했습니다. 영어·중국어도 유지하며, 사용자 입력·명령 출력·기술 진단 원문과 외부 MCP 결과는 보존합니다.
- ripgrep 15.2.0 Windows amd64를 라이선스·버전·크기·SHA-256과 함께 번들링합니다. 기존 검색과 설치·업데이트 경로를 사용합니다.
- MCP discovery의 잘못된 도구 항목이 SDK에서 panic을 일으키기 전에 검증하고 마지막 정상 목록을 유지합니다.
- Windows 설정 정규화가 사용자 프로젝트의 ACL을 변경하지 않도록 했습니다. AgentDock 자체 데이터 보호는 유지합니다.
- Core 정지 시 runtime root와 실제 프로세스 역할을 확인하여 형제 controller와 다른 설치의 Core를 보존합니다. 다른 사용자의 프로세스처럼 열 수 없는 같은 이름의 프로세스는 종료 대상으로 선택하지 않으며 상태 조회·정지를 실패시키지 않습니다.
- 기존 예약 작업과 명시적 복구 입력에서만 구형 action 및 schema 1 호환을 허용합니다. 소유권·원래 권한·복구 순서 검사는 유지합니다.
- Setup 결과 파일이 일시적으로 공유 잠금 상태인 경우 기존 대기 기한 안에서 다시 읽습니다. 접근 권한 오류·손상된 JSON·다른 실행의 결과를 성공으로 처리하지 않습니다.
- Setup이 사전 검사 등에서 거부되어 롤백할 때, 예약 작업을 실제로 변경하지 않았다면 기존 AgentDock 예약 작업을 중지하지 않습니다. 실행 중인 Core가 멈춘 채 남지 않습니다.
- Tailscale Funnel 공개 검증이 시간 초과되면 빠른 실패와 같이 검증 대기 상태로 기록합니다. 이전 성공 기록이 다시 "Ready"로 표시되지 않습니다.
- 제어판의 로컬 Core 요청(상태 확인·설정 변경)이 시스템 프록시와 리다이렉트를 사용하지 않습니다. 로컬 인증 토큰이 프록시로 전달되지 않습니다.

## 배포물과 설치

`AgentDockSetup-amd64.exe`는 오프라인 설치파일이며 `agentdock_windows_amd64.zip`은 동일 소스의 Windows x64 payload입니다. `install.ps1`, 파일별 SHA-256, 빌드 보고서와 검증 범위를 함께 제공합니다. 제품 파일은 **Authenticode 서명이 없는 unsigned 빌드**입니다. 동봉한 cloudflared는 공식 서명을 검증합니다.

기존 설치의 설정·보호된 자격 증명·사용자 데이터를 유지하는 업그레이드를 사용하세요. 원래 사용자가 아닌 다른 계정에서 기존 설치를 덮어쓰지 마세요. 원시 오류와 복구 자료가 남아 있다면 먼저 해당 설치 상태를 확인하세요.

## 검증 범위

이 배포물은 GitHub Actions를 거치지 않고 로컬 Windows x64 환경에서 빌드했습니다. 검증은 두 단계로 나뉩니다.

- 직전 소스 `2ae798f`는 GitHub Actions 실행 36368050134에서 Linux·Windows 회귀, native 복구, 한국어 WPF 표시, 실제 Setup 설치·반복 설치·repair·제거, 1.1.16102 기준판에서의 업그레이드와 실패 롤백 검증을 통과했습니다.
- 이후 추가한 위의 마지막 세 가지 수정은 로컬 회귀로만 확인했습니다. 이 배포 파일 자체로 실제 설치·업그레이드 시험을 다시 수행하지는 않았습니다.

`build-report.json`과 `verification-scope.json`에 실제 소스 SHA와 검증 범위를 기록했습니다. 물리 모니터·키보드 수동 검증과 코드 서명을 수행했다는 의미는 아닙니다.

## 유지한 구조

별도 runtime host, Origin pipe, epoch/state 시스템이나 새 시험 프레임워크를 추가하지 않았습니다. 기존 WPF 검사의 중복 실행은 제거하고 한 번의 native acceptance 결과를 사용합니다. 현재 배포 범위는 Windows x64이며 다른 플랫폼의 정식 배포를 포함하지 않습니다.
